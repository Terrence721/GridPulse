GridPulse — testing strategy

Three layers, run every time — none of them substitute for the others.

A green test suite and a clean build have never once been treated as "done" in this repo. Every feature gets verified against a real running stack before it's called finished — that habit is what actually found 21 of this project's real bugs, not code review.

xUnit · 63 tests

Unit testsEF Core InMemory, hand-rolled fakes — no mocking library

Proves
Idempotency and rollup math, rate-plan arithmetic (including exact tier-boundary and midnight-wraparound cases), ESPI's XML shape, and Stripe webhook signature verification — using Stripe.net's own EventUtility.GenerateSignatureHeader rather than a live connection.
Blind to
Real Kafka, real Postgres, real service wiring, and real external APIs — every dependency here is faked or in-memory by design.
Missed it: FakeStripeCheckoutSessionCreator always succeeds regardless of amount — no unit test could ever see Stripe's real $0.50 minimum reject a tiny invoice.
Aspire.Hosting.Testing

One integration testboots the real, full 10-resource distributed app

Proves
A real reading actually flows through real Kafka and real Postgres, end to end, with every service — including the always-running Meter Simulator — genuinely wired together, not just individually buildable.
Blind to
Anything requiring a human in a real browser — Stripe's hosted Checkout page needs an actual card form filled in, which no automated test here attempts.
Caught it: this exact test unexpectedly failed when a real, tiny invoice from the live Meter Simulator crashed Billing's entire host over Stripe's $0.50 minimum — a bug the unit-test layer structurally could not see.

Live manual verificationthe real running app, every feature, every time

Proves
The thing actually works for real: a real Checkout Session paid with Stripe's real test card, a real webhook signature verified, exact values cross-checked against real Postgres rows — not asserted from reading the code.
Blind to
Nothing structurally — but it's manual, so it only covers what actually gets exercised by hand, and doesn't run automatically in CI.
Caught it: the phantom empty-AccountId account in ESPI's UsagePoint collection — 19,888 real rows left by a long-dead orphaned process, invisible to any test using clean synthetic data.

All three run together, not as substitutes — a passing unit suite plus a passing integration test still hadn't proven a real card could actually be charged until someone opened the real Checkout URL and paid it.
